# Данные

Все данные лежат в `data/*.json`. Код сайта их только читает.

| Файл | Что внутри |
|---|---|
| `meta.json` | `schemaVersion`, `updatedAt` (ГГГГ-ММ-ДД), примечание |
| `sources.json` | словарь источников: `id → {name, url}`; `url: null` для каналов без ссылки |
| `waters.json` | водоёмы: уровень, число видов, рекорд, справка, история |
| `spots.json` | точки: `water`, `fish`, `coord` (`X:Y`) или `place`, `bait`, `clip`, `note`, `verified`, `sources` |
| `reels.json`, `rods.json` | таблицы снастей |
| `builds.json` | готовые сборки |

У каждой записи есть `sources`: список id из `sources.json`. Сайт показывает их в карточке.

## Проверка

`npm run validate` проверяет уникальность id, существование водоёмов и источников, формат координат,
диапазоны чисел, дату обновления. Те же проверки запускаются в CI и перед сборкой.

## Добавление точек

CSV (UTF-8, разделитель `,` или `;`) со столбцами `water, fish, coord, place, bait, clip, note, verified`.
`water` можно писать названием или id. Нужно ровно одно из `coord` или `place`.

```
npm run import -- --file my-spots.csv --source my-notes --dry-run   # посмотреть, что добавится
npm run import -- --file my-spots.csv --source my-notes             # записать
npm run check
```

Источник (`my-notes`) должен быть описан в `data/sources.json`. Дубликаты (тот же водоём, рыба и
координата) пропускаются, после слияния данные проверяются, и при ошибке ничего не записывается.

## Что нельзя импортировать

Импортируйте только свои записи и данные, которые автор разрешил использовать. Содержимое сайтов
rr4farmtrof.ru (Мальцевидзе) и справочников Potryasov Game защищено авторским правом, а часть точек
на rr4farmtrof скрыта за PRO-доступом. Автоматическое копирование без разрешения авторов не делается.
Черновик письма с просьбой о разрешении лежит в `docs/PERMISSION.md`.

## Сбор из Telegram

`data/channels.json` задаёт публичные каналы. `npm run fetch` читает их веб-версию (`t.me/s/<канал>`),
ищет посты, где рядом со словами «координаты» или «точка» стоит пара `X:Y` и упомянут известный водоём,
и кладёт кандидатов в `data/inbox.json`. Хранятся только факты (водоём, рыба, координата, наживка) и ссылка
на пост, текст постов не копируется. Прогресс по каналам лежит в `data/inbox-state.json`.

Кандидаты на сайт не попадают. Проверьте их по ссылке на пост и примите:

```
npm run promote -- --list
npm run promote -- --ids id1,id2      # в справочник (поле verified:false сохраняется в данных, на сайте метка не показывается)
npm run promote -- --reject id3
```

Автоматически раз в сутки это делает `.github/workflows/update-data.yml`: он запускает сбор и открывает
pull request с новыми кандидатами. Парсер эвристический, поэтому слепо принимать результат нельзя.
Если автор канала просит не использовать его посты, уберите канал из `channels.json`.

## Прочность с износом (data/gears.json)

955 записей, источник: калькуляторы Potryasov Game (https://potryasovgame.ru/page114271846.html и соседние страницы),
данные взяты из HTML-страниц, присланных владельцем справочника. Поле `kind`: `reel` (прочность ведущей шестерни) или
`rod` (прочность бланка), `category`: катушки `spin`, `power`, `baitcast`, `lp`; удилища `float`, `spinning`, `bottom`, `casting`, `sea`.
Формула автора: 30% прочности не изнашивается, `текущая = база × (0,3 + 0,7 × (1 − износ))`.
Записи с нулевой прочностью в источнике (у автора значение не заполнено, 32 шт.) не загружены.
Значения могут отличаться от столбца «Мех., кг» таблицы катушек: таблица обновлялась в марте 2025, калькуляторы в 2026.

## Расчётные сборки

`npm run builds` пересобирает сборки с `calculated: true` из таблиц удилищ и катушек (`scripts/lib/gen-builds.mjs`).
Правила: тест катушки должен лежать в диапазоне теста удилища; болонка берёт катушки с фрикционом до 9 кг, джерк от 17 кг;
леска не прочнее фрикциона, поводок 70-80% от лески; «прочная» сборка даёт максимум суммы прочности удилища и механизма катушки в пределах уровня.
Ручные сборки скрипт не трогает. Тест следит, чтобы сохранённые расчётные сборки совпадали с расчётом.
